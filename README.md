# DAILY REPS

英語トレーニングの記録アプリ。1ファイル（`index.html`）で動きます。

## 控え（タスクの `note`）の書き方

**控えの絶対条件は、いつ見ても手順が分かること。** 段は**4つだけ**で、この順番に並べます。

```
やり方 → コツ → 効果 → 素材
```

**この4つ以外の段は作りません。** 理由・決まり・判定のしかたは、コツか効果に畳みます。

- **1行目は一覧に常に表示される「まとめ」。** 長い文を書くと一覧が潰れます
- `■ ` で始まる行が小見出し。**半角スペース必須**
- `{{語}}` はマーカー。**`MARK` に登録済みの語だけ**。未登録の語はただの文字として出ます（壊れませんが色が付きません）。**枠の名前を変えたら `MARK` も直すこと**
- `→` は弱めた矢印になります
- **架空の例文字列（`〇〇` や `abc-xyz` のような仮の文字列）は書かない。** 実物を書くか、取り方だけ書く
- `note` は JS の1行文字列です。改行は `\n`（2文字）。**本物の改行を入れるとリテラルが閉じて壊れます**

### 直したあと

`DEFAULT_TASKS` を直したら **`TASKS_REV` を+1**。別途 **`sw.js` の `CACHE` も+1**。
**別のカウンタなので揃えません。** `TASKS_REV` を上げて消えるのは端末側の手編集だけで、
チェックの記録は残ります。

**枠を増やしたり消したりしたら、次の3つも必ず見てください。**

| | 直す場所 |
|---|---|
| 残り時間の計算 | `MINUTES`（id と分） |
| 先にやる順番 | `ORDER`（id の並び） |
| 一言の文面 | 消した枠の名前や id が本文に残りやすい |


## 置き場は3つから選べます

| 開き方 | 保存先 | 設定 |
|---|---|---|
| **Cloudflare Pages**（おすすめ） | D1 の1行 | 鍵を1本入れるだけ |
| ホーム画面アプリ／ブラウザ | シークレット Gist の `daily-reps.json` | トークンと Gist ID |
| Claude の Artifact | Artifact 自身の `data/state.json` | 不要 |
| 設定しない | その端末の中だけ | — |

鍵があれば Cloudflare を使い、無ければ Gist に落ちます。どちらの場合も、
まず端末内に保存してから送るので、通信がなくても記録は消えません。

## Cloudflare に置く（無料）

GitHub のトークンを端末に持たせずに済みます。鍵はこのアプリ専用で、
漏れてもこのアプリの記録しか触れません。

Cloudflare は新しく作るものを Workers に寄せているので、Workers で動かします。
`wrangler.toml` と `worker.js` が入っているので、設定は要りません。

| ファイル | 役目 |
|---|---|
| `wrangler.toml` | 名前・静的ファイルの場所・D1 の割り当て |
| `worker.js` | 入口。`/api/state` だけを受けて、あとは静的ファイルに任せる |
| `functions/api/state.js` | 置き場の中身。Pages で動かすときも同じものが使われる |
| `.assetsignore` | 配らなくていいファイル（設定や道具） |

静的ファイルの取り出しは Worker の呼び出し回数に数えられません。
数えられるのは記録のやりとりだけなので、1日10万回の枠はほぼ減りません。

### 一度だけの用意

1. **D1 を作る** — ストレージとデータベース → D1 → 作成（名前は `daily-reps`）
   できたら、その ID を `wrangler.toml` の `database_id` に書く
2. **つなぐ** — コンピュート → Workers → Connect to Git → このリポジトリ → デプロイ
   （ビルドコマンドは空、デプロイコマンドは `npx wrangler deploy` のまま）
3. **鍵を入れる** — できた Worker の Settings → Variables and Secrets →
   種類 **Secret**、名前 **`REPS_KEY`**、値は長いランダム文字列
4. **置き直す** — 鍵は入れただけでは効かないので、デプロイし直す
5. **アプリ側** — 発行されたアドレスを開く → 同期チップ → 鍵を貼る →
   「つながるか調べる」→「この鍵でつなぐ」

表は作らなくて構いません。無ければ Function が自分で作ります。
鍵はリポジトリに入れません。端末の `localStorage` にだけ残ります。
`database_id` は秘密ではありません。アカウントの中で置き場を指す名前です。

### やりとりの決まり

```
GET  /api/state              → {body, rev}
PUT  /api/state  {body, rev} → {ok:true, rev}
                               版が古ければ 409 {conflict:true, body, rev}
```

記録を書くたびに**版（rev）が1つ増えます**。送った版が置き場の版と違えば
409 が返るので、受け取った最新と突き合わせてから出し直します。
Gist と違って「読んでから書くまでの間に割り込まれる」隙がありません。

### 無料枠

1日あたり Worker 10万リクエスト、D1 の書き込み10万行・読み込み500万行、
保存5GB。このアプリは1日あたり読み800・書き40ほどなので、桁が3つ足りません。
上限に達しても課金されず、リクエストが失敗するだけです。

### うまくいかないとき

同期チップ →「つながるか調べる」。返ってきた番号で切り分けられます。

| | 意味 | すること |
|---|---|---|
| 401 | 鍵が違う | `REPS_KEY` と、アプリに入れた鍵を揃える |
| 404 | `/api/state` が無い | `worker.js` が入口になっているか見る |
| 500 | 割り当て漏れ | D1 が `DB` という名前で割り当たっているか見る |
| 届かない | 場所が違う | 発行されたアドレスから開いているか見る |

## 自動同期

ヘッダーの同期チップをタップすると設定できます。記録の置き場所は開き方で変わります。

| 開き方 | 保存先 | 設定 |
|---|---|---|
| ホーム画面アプリ／ブラウザ | シークレット Gist の `daily-reps.json` | 端末ごとに1回。**つなぐリンク**を貼るのが最短 |
| Claude の Artifact | Artifact 自身の `data/state.json` | 不要 |
| 設定しない | その端末の中だけ | — |

どの場合も、まず端末内に保存してから送るので、通信がなくても記録は消えません。

### 端末ごとの設定

瞬間英作文（`sunkan-333`）・My Dictionary（`dictionary-22`）と同じ作りです。
1枚のシークレット Gist に、アプリごとに別ファイルを置いて同居します。

| アプリ | Gist の中のファイル |
|---|---|
| 瞬間英作文 | `sunkan-data.json` / `sunkan-inbox.json` |
| My Dictionary | `mydict-data.json` |
| DAILY REPS | `daily-reps.json` |

書き込みは自分のファイルだけを名指しするので、ほかのアプリのぶんは踏みません。

**いちばん楽な入れ方**は「つなぐリンク」です。
瞬間英作文の ⚙ →「つなぐリンクをコピー」で作ったものを、
このアプリの同期チップ →「つなぐリンクを貼り付ける」に貼って「貼り付けたリンクでつなぐ」。
トークンと Gist ID がそのまま入るので、iPhone でトークンを打ち込まずに済みます。
リンクの形は3つのアプリで共通です。

```
<ページの URL>#pair=base64url({"t": トークン, "g": Gist ID})
```

`#pair=` 付きの URL で開いた場合も、その場で受け取ってアドレスから消します。

**Gist ID は入れなくても構いません。** トークンだけで「同期を始める」を押すと、
アプリがアカウントの Gist を見て置き場を決めます。

1. `daily-reps.json` がある Gist（＝前に使っていた置き場）
2. `sunkan-data.json` / `mydict-data.json` がある Gist（＝瞬間英作文と同居）
3. どちらも無ければ、シークレット Gist を新しく作る

起動時は 1 と 2 を探すだけで、**作りません**。同じトークンの端末が同時に立ち上がると
置き場が2つできて記録が分かれるためです。作るのは「同期を始める」を押したときだけです。

[トークン](https://github.com/settings/tokens/new?scopes=gist)は scope `gist` で作ります。
**classic（`ghp_` で始まるもの）が必要です。** fine-grained（`github_pat_`）は Gist API に対応していません。

うまくいかないときは、同期チップ →「つながるか調べる」。
トークンの種類・GitHub に届いたか・置き場が見えるかを順に確かめて、失敗した理由をそのまま出します。

### GitHub への通信で気をつけること

リクエストに載せるヘッダーは **`Authorization: token …` と `Accept: application/vnd.github+json` の2つだけ**
（書き込みのときは `Content-Type` も）。`X-GitHub-Api-Version` のような追加のヘッダーを足すと、
ブラウザが事前確認（プリフライト）を挟み、許可されていなければ**送信前に失敗**します。
瞬間英作文の `sync.js` も同じ2つだけです。テスト（`headers` の確認）でこれを見張っています。

トークンと Gist ID はその端末の `localStorage` にだけ残り、リポジトリには入りません。

| 鍵 | 中身 |
|---|---|
| `dailyreps:sync:token` | トークン |
| `dailyreps:sync:gistId` | Gist ID |
| `dailyreps:sync:auto` | 自動同期の入切（`0` で手動だけ） |
| `dailyreps:sync:last` | 最後に揃えた時刻 |
| `dailyreps:sync:error` | 最後に失敗した理由（黙って止まらないため） |

### 突き合わせの決まり

- 読み込みは、開いたとき・アプリに戻ったとき・1分ごと
- 書き出しは約2秒のまとめ書き（連打しても1回）。Gist は上書きしかできないので、**書く直前にもう一度読んで突き合わせて**から書く
- 食い違いは **チェック1つ単位**で新しいほうを残す（`meta.marks[日付][タスク]` に切り替えた時刻を持つ）。
  そのため、2台が同じ日に別々のタスクをチェックしても両方残る
- 「この日のチェックを消す」は `meta.cleared[日付]` に時刻を置き、それより古いチェックを消す
- タスク一覧は最後に編集したほうを採用

記録の形は `index.html` の `normalize` / `mergeState` / `serialize` が全てです。
古い形（日ごとに1つの時刻を持つ v3、`meta` のない v2）も読めます。
v5 でタスクに `dayType`（`lesson` / `off` / `both`）が加わりました。
持っていない記録は `normalize` が `both` に寄せるので、古い記録もそのまま読めます。
v6 でタスクに `note`（名前の下に出す一行メモ）が加わりました。同じく `normalize` が空文字で補います。

### `data` ブランチについて

一時期このリポジトリの `data` ブランチに記録を置いていました。いまは使っていません。
Gist での同期が確認できたら消して構いません。

### 前の設定からの引き継ぎ

`dailyreps.token.v2` / `dailyreps.gist.v1` に入っていた設定は、起動時に新しい鍵へ移して古いほうを消します。

## Artifact 用ページを作り直す

`index.html` を直したら、次を実行して出てきたファイルを公開します。

```sh
python3 tools/build-artifact.py
# → build/daily-reps.artifact.html
```

Artifact は `<html>`／`<head>`／`<body>` を自前で付けるため、その外枠だけを外したページを作ります。
アプリのコードは `index.html` の1本のままです。

## 記録が消えたとき・端末をつなぎ直すとき

### まず知っておくこと

**iOS はホーム画面の Web アプリを削除すると、そのアプリの保存データごと消します。**
アイコンを入れ替えるために削除して追加し直すと、端末側の記録と同期設定の両方が消えます。
消える前に「バックアップを保存」を押しておくこと。

記録そのものは Cloudflare D1 の `state` テーブルに JSON 1行（id = 1）で入っています。
端末側が消えても、置き場が無事なら戻せます。

### 置き場に記録が残っているか見る

Cloudflare → D1 → `daily-reps` → Console。

```sql
SELECT rev, datetime(updated/1000,'unixepoch','+9 hours') AS 最後に書いた時刻,
       length(body) AS 文字数
FROM state WHERE id = 1;
```

文字数が数千以上なら残っています。中身を直接取り出すなら `SELECT body FROM state WHERE id = 1;`。
出てきた文字列を `.json` で保存すれば「バックアップを読み込む」でそのまま読めます。

### つなぎ直す

**空の端末をつないでも記録は消えません。** `btnCfSave` は `SYNC.restart()` →
`await pull()` の順で動き、`pull()` は先に置き場を読んでから突き合わせます。
突き合わせは日付×タスクごとに「最後に触った時刻」が新しいほうを残すので、
時刻が全部 0 の空の端末は必ず負けます。

1. 鍵（`REPS_KEY`）を用意する
   - すでにつないである端末があるなら、同期設定の鍵の欄の 👁 を押すと表示される
   - 無ければ Cloudflare → Workers & Pages → `daily-repsssss` → 設定 →
     変数とシークレット → `REPS_KEY` の鉛筆で**新しい値に入れ替える**（値は読み出せない）。
     入れ替えても D1 の記録には触れない。保存後に Deploy を押す
2. アプリ左上の同期チップを押す → 鍵を入れる → 「つながるか調べる」→「この鍵でつなぐ」

### 「つながるか調べる」で HTTP 404 が出るとき

**原因はほぼ、アプリを Worker 以外の URL で開いていること。**
「置き場の場所」が空のとき、アプリはいま開いているドメインの `/api/state` を叩きます。
GitHub Pages などから開いていると、そこに `/api/state` は無いので 404 になります。
この設定も端末の控えに入っているので、アプリを消すと一緒に消えます。

直し方は2つ。

- **Worker の URL から開き直す（おすすめ）**。Cloudflare → Workers & Pages →
  `daily-repsssss` のページ上部に出ている URL を Safari で開き、そこから
  ホーム画面に追加する。同じドメインになるので「置き場の場所」は空のままでよい
- いまの URL のまま使うなら、「置き場の場所」に Worker の URL をフルで入れる
  （末尾は `/api/state`）

### 鍵を入れ替えるときの注意

同じ `REPS_KEY` を使っている別のアプリや端末は、入れ替えた時点でつながらなくなります。
2 秒ドリル（Section）も使っているなら、そちらにも新しい鍵を入れ直すこと。
